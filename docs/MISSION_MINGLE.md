# ミッション・ミングル

> 名称は仮称です（変更の可能性があります）。

> 本番反映の順序とロールバック手順は `docs/GROUP_PLAY_SETUP.md` の「本番反映の順序」「ロールバック手順」を参照してください（migration を本番に適用してからデプロイします）。

仕様の原本は `docs/games/mission-mingle.md`（リポジトリ直下の `docs/`）です。このファイルは実装の運用メモです。

## 遊び方

3〜8人で参加し、代表者がルームを作ります。参加者は招待URLまたはQRから呼び名を入力して参加します（開始後の途中参加はできません）。集まり全体がゲームで、ターンはありません。

1. 代表者がロビーで、時間（30／60／120分、既定60分）、難易度（ゆるめ／ふつう／攻め）、場面（飲み会／合コン・街コン／懇親会）、「席が決まっている」のON/OFFを選んで開始します。
2. 各自に、他の人に見えない「相手を知る行動」の指令が3つ届きます。指令は難易度の組み合わせが決まっていて、ゆるめは[1,1,2]、ふつうは[1,2,3]、攻めは[2,3,3]です。
3. スマホはしまって、普通に会話します。達成したら画面を長押しして指令を出し、こっそり「できた」を押します（自己申告です。他の人は確認しません。取り消せます）。
4. 終了時刻になると、全員の画面が「時間です！」になります。記録し忘れた指令は、答え合わせが始まるまで記録できます。
5. 代表者が「答え合わせスタート」を押すと、全員の端末で1人ずつ同時に公開します。代表者が実際の終了時刻から3分操作しなければ、参加者の誰でも「答え合わせスタート」「次の人へ」「終了」を押せます（代表者が不在でも止まりません）。答え合わせが始まった時点で、達成していない行（未達成・パス・交換済み）と交換の記録をDBから削除します。公開するのは、その人が**達成した指令だけ**です（未達成、パス、交換済みは表示しません）。個人の順位はなく、「みんなで◯個達成！」と、本人の称号だけを出します。

### パスと交換

- パスは何度でもできます。パスした指令の枠は空いたままで、補充しません。
- 交換は1人1回です。未達成の指令を、同じ難易度の別の指令に引き直します。交換した後の指令は元には戻りません。
- 聞かれた人は、答えなくて構いません。画面にも明記します。

### 時間と延長

代表者は、指令フェーズ中に「延長 +15分」を最大2回まで使えます（ルームの24時間の期限を超える延長はできません）。「今すぐ答え合わせ」で早めに終えることもできます。このとき終了時刻が、押した時刻に書き換わります。

### ポケット画面

指令フェーズ中の通常表示は、暗い無地の背景に終了時刻（「21:30 まで」）だけです（ロゴも案内文も、「指令」などの語も、表示と`aria-label`のどちらにも出しません。代表者だけに小さな「…」のメニューがあります）。画面を約0.5秒長押しすると指令が出て、5秒操作しない、ほかのアプリに切り替える、画面を閉じる、のいずれかで自動的に隠れます。開始直後に1回だけ出る「指令が3つ届きました」の導入画面も同じ条件で隠れ（隠れた時点で導入は済んだ扱い）、時間切れ後の「記録し忘れはありませんか？（長押しで確認）」も長押しで見る方式で、未達成・パスの文面は画面に出しません。パスは1段の確認を挟みます。達成の記録は小さな「記録しました」という表示だけで、Androidでは30msだけ振動します。タブのタイトルは「Mingle.Cards」のままで、指令の文面は`document.title`にも通知にも出しません。

### 終了の合図

Web Pushは使いません。終了時刻を全員の画面に出し、代表者の端末が開いていれば終了時刻に表示と短い音（既存のカードめくり音。音オフの設定に従います）で知らせ、ほかの端末は開いた時点で最新の状態に追いつきます。代表者が実際の終了時刻から3分操作しなかった場合は、参加者の誰でも答え合わせを始められます。

## 指令カード

`dist/data/mission-mingle-cards.js`に151枚あります（`missionCardDefs`が原本、`missionCards`が正規化した公開配列）。相手を知る行動だけで、自己開示型はありません。`{target}`は表示のときに相手の呼び名へ置き換えます（DBには文面を保存しません）。席に依存する指令（`target: 'seat'`）は、代表者が「席が決まっている」をONにしたときだけ配ります。店舗QRから作ったルームでは、初期値がONです。

## 配布アルゴリズム

`server-side/mission-mingle.mjs`の純関数`dealMissions`（乱数を注入できます）が、開始時に全員分を決めます。

- **ハード制約**（常に守ります）: 同じ指令IDを2人に配らない（交換で外れたIDも配り直さない）／相手は自分以外／同じ相手に同じ話題（`topic`）の指令を2人以上に配らない／1人の3枚は難易度の並びがプリセットどおり。
- **ソフト制約**（満たせなければ段階的に緩めます）: 3枚のカテゴリを重ねない／3枚で同じ相手を選ばない／席の指令は1人1枚まで／相手に選ばれる回数の差を2以内にする。
- 手順は、難しい枠から順に、条件に合う指令を乱択し、相手は選ばれた回数が最も少ない人から選びます。行き詰まったらやり直し（各段階で最大50回）、それでも埋まらなければ席の制限、同じ相手の重複、カテゴリの重複、相手の偏り、の順に緩めます。すべて失敗すると`MISSION_POOL_EXHAUSTED`（409）です。現在のカードでは、3〜8人×3プリセット×3場面×席あり/なしのどの組み合わせも、緩めずに配れます。
- 交換（`dealReplacement`）は、同じ難易度で、配布済みのID（交換・パス済みも含む）を除き、現在有効な指令と（相手, 話題）が重ならないものを1枚引きます。DBの一意制約に当たった場合は、サーバーが最大3回引き直します。

## 状態遷移

```
lobby -(configure: 代表者 / start: 代表者, 3〜8人)-> mission
mission -(終了時刻に到達: 取得時に遅延遷移 mission_expire / end_now: 代表者)-> reveal_ready
mission -(extend: 代表者, +15分, 最大2回)-> mission
reveal_ready -(reveal_start: 代表者。終了時刻の3分後からは誰でも)-> reveal(cursor 0)
reveal -(reveal_next: 代表者)-> reveal(cursor+1) ... -> 最後の1人でゲームの行を削除、room を ended に（summary は mission_results から5分だけ表示）
reveal -(finish: 代表者。実終了時刻+3分後からは誰でも)-> ended
どの phase でも -(finish: 代表者)-> ended（ゲームの行ごと削除し、room を ended に）
```

最後の1人を公開した時点で、ゲームの行ごと（指令・交換・公開順）をすぐ全部削除し、room を`ended`にします（代表者のルーム上限を消費しません）。最後の結果画面を全端末に届けるため、結果表示用の最小データ（達成合計と、各人の自分の達成数・称号）だけを`mission_results`に`result_expires_at`（終了時刻＋5分）まで残し、その後は自動で削除します。削除は、状態を取得したときに期限切れの行を見つけた場合と、既存のcleanup（`cleanupExpired`が`result_expires_at`の過ぎた結果を削除）で行い、cronは追加していません。5分経過後の状態は`ended`の最小応答です（summary の`pollMs`は0で、取得は止まります）。端末は一度受け取ったまとめと答え合わせの内容をメモリに保持し、`ended`に変わっても表示を消しません（再読み込みすると見られません）。以前の「まとめ以降は誰でも終了で削除できる」はやめました（5分は誰も切り上げられません）。`finish`はロビー・指令中・答え合わせ中だけで、途中終了は結果を残さず即全削除です。

指令1つの状態は、`active`から`achieved`（取り消せば`active`に戻る）、`passed`（最終）、`swapped`（交換。最終）のいずれかです。`achieve`/`unachieve`/`pass`は`mission`と`reveal_ready`で受け付け、`swap`は`mission`で終了時刻前だけです。

`group_rooms.status`との対応は、`lobby`が`lobby`、`mission`〜`reveal`が`playing`、最後の1人を公開した後（まとめの表示中も、その後も）は`ended`です。`mission_games.phase`に`summary`/`ended`はありません。

## サーバー側の秘密保持

- 指令は本人の分だけ返します（代表者にも他人の分は返しません）。指令フェーズ中は、他人の達成数もルーム全体の達成数も、どの形でも返しません。
- 答え合わせでは、公開順で「今の人まで」の、達成した指令だけを取得して返します（`member_id=in.(…)&status=eq.achieved`）。未達成・パス・交換済みは取得もしません。
- `summary`はゲーム終了後の5分だけ返し、達成数の合計と、本人だけの達成数・称号を含みます（他人の達成数・称号・指令、配った総数や未達成数は返しません。答え合わせ中に受け取った内容は端末のメモリに残るだけです）。
- 保存するのは、指令ID・話題タグ・難易度・相手のmember ID・状態フラグ・枠番号と、交換の使用回数だけです。回答の内容、達成した時刻、誰が誰に何を聞いたかは保存せず、回答の入力欄もありません。
- `group_rooms.cards`には中立の仮カード6枚だけを入れ、指令の文面は入れません。

## 同時操作とポーリング

達成・パス・交換は`revision`を要求しません（参加者の個人操作がほかの人の画面を古くしないため）。`revision`を必須にするのは`start`だけです（名簿が変わった状態で開始させないため）。ほかの代表者の操作は、ochi/one_cutと同じくphaseの照合で二重実行を防ぎ（`reveal_next`は表示中の位置`cursor`を送り、食い違えば`MISSION_PHASE`）、終了時刻をまたいだ操作も`MISSION_PHASE`（409）になります。クライアントは409を文言なしで静かに取り直します。

`GET /api/group/rooms/:id`は`mission.pollMs`（推奨の取得間隔）を返し、クライアントはこれに従います。ロビー、答え合わせ待ち、答え合わせは1秒、指令フェーズ中は30秒（画面表示中だけ。非表示のタブは取得せず、表示に戻ったとき・フォーカス・オンラインになったときに即時取得）、終了前の60秒は5秒、まとめ（summary）と終了後は`pollMs`が0で取得を止めます（失敗したときは最大15秒まで延ばします）。答え合わせの間隔を2秒に落としたいときは`MISSION_POLL_MS.reveal`（`server-side/mission-mingle.mjs`）を変えます。

## 保存と期限

端末には、ルーム専用キー`mingle.mission.room:<id>`で参加資格情報と「導入画面を見た」フラグだけを`localStorage`の同じJSON（期限つき）に保存します（最長2時間スマホをしまうため。期限は`min(ルームの期限, 保存から24時間)`で、room が ended になった（まとめに入った）のを確認した時点、または401/403/404/410で削除します）。指令の文面は端末に保存しません。放置したルームは24時間後にアクセスできなくなり、物理削除は既存のcleanupで行われ、外部キーのcascadeで`mission_games`、`mission_assignments`、`mission_swaps`、`mission_results`も消えます。代表者が終了を押した場合は、その場でゲームの行ごと削除します。

## SQLと環境

次の順で、使い捨てDBに適用してから本番へ適用します。本番DBへ自動適用しません。

1. `supabase/migrations/202610080001_group_rooms.sql`（および既存のグループ関連migration）
2. `supabase/migrations/202610150001_minority_topic.sql`
3. `supabase/migrations/202610160001_question_wolf.sql`
4. `supabase/migrations/202610170001_group_game_types.sql`（`group_rooms.game_type`のCHECKを新ゲーム共通で張り替えます）
5. `supabase/migrations/202610170004_mission_mingle.sql`（このゲーム。CHECKは書き換えません。再実行できます）

`mission_games`、`mission_assignments`、`mission_swaps`、`mission_results`は`service_role`専用で、クライアントからの直接読み書きとRPC実行は拒否します。状態遷移はすべて`security definer`のRPC（`mission_create_room`、`mission_configure`、`mission_start`、`mission_set_status`、`mission_swap`、`mission_expire`、`mission_end_now`、`mission_extend`、`mission_reveal_start`、`mission_reveal_next`、`mission_finish`）で行い、開始時刻と終了時刻はDBの時計で決めます。追加のenvやAPIキーはありません。指令ごとの達成率などの利用統計は取りません。

エラーコードは`MISSION_NOT_OWNER`（403）、`MISSION_PHASE`、`MISSION_SWAP_LIMIT`、`MISSION_EXTEND_LIMIT`、`MISSION_POOL_EXHAUSTED`、`MISSION_UNAVAILABLE`（以上409）です。RPCが古い読み取りを拒否したとき（`MISSION_INVALID`、`MISSION_PARTICIPANTS`）は、サーバーが`GROUP_STALE`（409）に直し、クライアントが取り直します。
