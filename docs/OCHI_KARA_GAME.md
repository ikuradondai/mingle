# オチから話して

> 名称は仮称です（変更の可能性があります）。

> 本番反映の順序とロールバック手順は `docs/GROUP_PLAY_SETUP.md` の「本番反映の順序」「ロールバック手順」を参照してください（migration を本番に適用してからデプロイします）。

## 遊び方

2〜8人（3人以上がおすすめ）で参加し、代表者がルームを作ります。参加者は招待URLまたはQRから呼び名を入力して参加します。開始すると各自のスマホに、話の最後の一文（オチ）が秘密で1枚ずつ配られます。

話す順番は開始時にランダムで決まり、全員が1回ずつ話し手になります（作成時に2周も選べます）。1ターンの流れは次のとおりです。

1. 話し手が「話しはじめる」を押し、60秒で、そのオチに着地する話をします。実話でも作り話でも構いません。
2. 話し終えたら「話し終えた：実話だった／作り話だった」を押します。正解はこの時点で秘密のまま登録されます。
3. 聞き手は「実話だと思う／作り話だと思う／わからない（パス）」から1つ選んで投票します。投票は変更できません。
4. 全員の投票がそろうと、話し手が「正解を明かす」を押します。代表者が代わりに押すこともできます。
5. 結果（正解、票数、一人ひとりの予想、自分の今回の得点）を見て、代表者が次の話へ進めます。他の人の得点は出しません。

投票するのは「実話か作り話か」の予想だけで、話のうまさは採点しません。

### パス

- 話し手は「別のオチにする」を1ゲームに1回だけ使えます（配られた直後、または自分の番の準備中）。
- 話し手は何度でも「今回は聞く側にまわる」を選べます。理由は聞きません。
- 聞き手は「わからない（パス）」を選べます。得点は入らず、話し手の得点判定にも数えません。

### 得点と称号

- 聞き手は予想が当たれば+1です。
- 話し手は、パス以外の票の過半数を外させたら+1です（同数は+0、全員パスも+0）。
- 最後の結果画面は**称号だけ**です。「名探偵」（聞き手として最も得点が高い人）と「ミステリアス賞」（話し手として最も得点が高い人）の受賞者名だけを全員に発表します。同点は全員に贈り、全員の得点一覧も順位表も出しません。得点が1点もない称号は出しません。
- 得点は本人にだけ見せます。各ターンの結果画面は自分の今回の増減（+1／+0）だけ、最後の画面は自分の合計（聞き手 N点／話し手 N点）だけです。他人の得点は、サーバーの応答にも含めません。

### 60秒タイマー

時間切れでも強制終了はしません。表示が「時間です！オチをどうぞ」に変わり、超過時間が増えていきます。残り10秒で色が変わり、カードをめくる音を1回鳴らします（音オフの設定に従います）。端末の時計ではなく、サーバーが返す`serverNow`を基準に残り時間を出します。

## 入口

通常利用では、質問テーマ一覧のゲーム棚にある「オチから話して（2〜8人）」からルームを作ります。ルーム作成には既存のログインが必要です。店舗利用では、卓上QRを読み込んだ店舗ランディングのゲーム入口から作成し、店舗の公開トークンはルーム作成時に検証されます。参加者の参加と操作にはログインを要求しません。

## 状態遷移

```
lobby -(start: 代表者)-> deal -(全員 confirm / force_ready)-> ready(t)
ready -(begin_tell)-> telling -(finish_tell: 話し手が答えを秘密登録)-> vote
ready / telling -(skip)-> skipped
vote -(全員投票 / close_vote)-> reveal -(reveal: 話し手または代理の代表者)-> result
result / skipped -(next_turn)-> ready(t+1) / 2周目の頭は deal / 最後は final
lobby〜途中の phase -(finish: 代表者)-> ended（ゲームの行を削除）
final ではゲームの行を全部削除し、room は ended になる。称号の受賞者と各人の得点だけが ochi_results に5分残り、その後は自動削除（state は ended の最小応答）
```

`vote`から`result`へ直接進む経路はありません。投票がそろっても`reveal`で止まり、`ochi_reveal`だけが`result`にします。

## サーバー側の秘密保持

- 配られたオチは本人にだけ返します（代表者にも他人の分は返しません）。引き終えた手札は返しません。
- 正解（`ochi_turns.truth`）は`result`になるまで誰にも返しません。話し手と代表者には「登録済みか」の真偽値（`myTruthLocked`）だけを返します。サーバーは`result`以外では`truth`列も投票の中身（`guess`）も取得しません。
- 話し手が語り終えた後は、オチの文が聞き手に必要になるため、`vote`以降は現在の話し手のオチの文を全員に返します（仕様のQ16）。隠す期間を延ばす場合は`server-side/ochi-kara.mjs`の`TURN_OCHI_PHASES`を変えます。
- 代表者が話し手の代わりに`finish_tell`を押した場合、代表者が送った答えは無視します（代表者は答えを知りません）。この場合の答えは`reveal`のときに入力します。

## 同時操作

参加者の`confirm`、`vote`、`swap`は`revision`を要求しません。それぞれ`turnNo`と本人の状態（確認済みか、投票済みか、`swapUsed`）とphaseで照合します。ほかの人の操作で`revision`が進んでも失敗しません。代表者の操作と話し手の進行操作（`begin_tell`、`finish_tell`、`skip`、`reveal`）は現在の`revision`を必須にします。

## 保存と期限

ルームへの参加情報を、そのルーム専用キーの`sessionStorage`へ保持します。オチ、正解、投票内容は端末へ保存しません。話は音声でその場で話すだけで、回答本文を入力・録音・保存する機能はありません。

ゲーム進行に必要な手札、投票（実話／作り話／パス）、正解の1ビット、得点だけをサーバーに一時保持します。最後の話が終わって結果発表（`final`）に入った時点で、ゲームの行ごと（ターン、投票、手札、正解、得点）をすぐ全部削除し、ルームは終了扱いになります（代表者のルーム上限を消費しません）。最後の結果画面を全端末に届けるため、結果表示用の最小データ（称号の受賞者と、各人の自分の点）だけを`ochi_results`に`result_expires_at`（終了時刻＋5分）まで残し、その後は自動で削除します。削除は、状態を取得したときに期限切れの行を見つけた場合と、既存のcleanup（`cleanupExpired`が`result_expires_at`の過ぎた結果を削除）で行い、cronは追加していません。5分経過後の状態は`ended`の最小応答です。端末は一度受け取った結果をメモリに保持するので、`ended`に変わっても表示は消えません（再読み込みすると見られません）。代表者が途中で終了した場合は、これまでどおりゲームの行ごと（得点も）即削除し、結果は残しません。放置したルームは24時間後にアクセスできなくなり、物理削除は既存のcleanupで行われ、外部キーのcascadeで`ochi_games`、`ochi_turns`、`ochi_votes`も消えます。

5. `supabase/migrations/202610170002_ochi_kara.sql`（このゲーム。CHECKは書き換えません）

`ochi_games`、`ochi_turns`、`ochi_votes`、`ochi_results`は`service_role`専用で、クライアントからの直接読み書きとRPC実行は拒否します。状態遷移はすべて`security definer`のRPC（`ochi_create_room`、`ochi_start`、`ochi_confirm`、`ochi_force_ready`、`ochi_swap`、`ochi_begin_tell`、`ochi_finish_tell`、`ochi_skip`、`ochi_cast_vote`、`ochi_close_vote`、`ochi_reveal`、`ochi_next_turn`、`ochi_finish`）で行い、得点もRPCの中で計算します。追加のenvやAPIキーはありません。利用統計は専用の集計を作りません。
