# ひとりだけ違うお題

## 遊び方

3〜8人で参加し、代表者がルームを作ります。参加者は招待URLまたはQRから呼び名を入力して参加します。各ラウンドで、多数派のお題と近い少数派のお題が配られます。各自が自分のお題だけを確認して伏せ、口頭でヒントを出し合った後、他の参加者へ秘密投票します。

最多票が少数派なら多数派の勝ち、少数派以外なら少数派の勝ちです。最多票が同数の場合は引き分けです。最大6ラウンドで、6ラウンド終了後はゲームを終了できます。代表者は途中で終了することもできます。

## 入口

通常利用では、質問テーマ一覧の「ひとりだけ違うお題（3〜8人）」からルームを作ります。ルーム作成には既存のログインが必要です。店舗利用では、卓上QRを読み込んだ店舗ランディングのゲーム入口から作成します。店舗の有効な公開トークンはルーム作成時に検証されます。参加者の参加と投票にはログインを要求しません。

代表者のルーム画面には参加用QRとコピー可能な招待URLが表示されます。QRを表示できない場合はURLを渡せます。

## 保存と期限

ルームへの参加情報と、ログイン後に戻るための情報（呼び名を含みます）を、そのルーム専用キーの`sessionStorage`へ保持します。お題本文、役割、投票内容は保存しません。ブラウザを再読み込みした場合はtokenを使って同じルームへ再取得します。保存領域を消した場合は参加し直します。

会話の回答を文字や音声で記録する機能はありません。ゲーム進行に必要な配役、確認状態、票はサーバーに一時保持し、ゲーム終了時に削除します。放置したroomは24時間後にアクセスできず、物理削除は後続アクセス時に行われます。結果表示後は次ラウンドまたは終了まで一時状態が残ります。

開始後に端末の保存領域を消した場合、その端末の参加tokenを失うため、同じ参加者としての再joinはできません。

## SQLと環境

`supabase/migrations/202610150001_minority_topic.sql`を、既存のグループルーム関連migrationとアカウント/店舗テーブルが適用済みの環境へ適用します。既存カードのグループプレイは2〜8人、新ゲームは3〜8人です。actionには現在の`revision`と`roundNo`を含めます。通常・店舗とも既存の認証とグループルーム境界を使い、少数派ゲーム用の`minority_create_room` RPCで作成します。店舗開始専用APIや追加env/APIキーはありません。店舗利用統計は既存カード開始/6枚完了集計のままで、このゲームの専用集計はありません。本番DBへ自動適用しません。
