# マイセット共有（alpha）

共有は、ログインした所有者が自分の非公開マイセットに対して明示的に開始します。`POST /api/account/sets/:setId/share` は最初の共有時だけURLトークンを作成し、同じ共有が有効な間は同じURLを返します。現在のリンク確認は `GET`、URLを作り直すときは `PUT`、停止するときは `DELETE /api/account/sets/:setId/share` を使います。新しいトークンは暗号学的乱数から作り、DBにはハッシュと所有者向けの再表示用トークンを保存します。`PUT` と停止はSupabase上の所有setをロックするトランザクション関数で処理します。

受信者向けの `GET /api/share/:token` はセット名、枚数、成人向けフラグだけを返します。質問本文や所有者のメールアドレスは返しません。`POST /api/share/:token/start` に参加者名と成人同意を送ると、その共有時点のスナップショットでプレイを開始できます。R18を含む場合は参加者全員の同意が必要です。参加者名はプレイ開始の検証にだけ使い、サーバーには保存しません。

共有リンクの受信者は登録なしで最初の6枚を遊べます。6枚終了後に続きを遊ぶには、通常のプレイと同じくログインまたは新規登録が必要です。共有ゲストの進行もこの制限に従い、認証後は同じ端末の続きから再開します。

共有停止、トークンの作り直し、マイセット所有者の退会後は新しい読み込みとプレイ開始ができません。停止前に受信者が取得したスナップショットや端末上の途中データを後から消すことはできないため、所有者向け画面でこの点を案内します。共有URLは一覧公開されず、APIレスポンスはキャッシュしません。SNS投稿文と広告表示はプレイ画面側で扱い、共有APIは担当しません。

設定時は、既存のaccounts/custom_cards migrationの後に `supabase/migrations/202610040001_shared_sets.sql` を実行します。公開リンクのtoken照合はサーバー内のservice roleで行います。このキーはブラウザへ返さず、未設定の環境では共有機能だけが利用不可になります。

## 広告設定の例

広告を使わない場合は何も設定せず、枠は表示されません。設定する場合は、公開ページの起動前に `globalThis.__MINGLE_AD_CONFIG__`（`dist/ad-config.js` の `DEFAULT_CONFIG` と同じ形式）へ次のような公開情報だけを渡します。

```js
globalThis.__MINGLE_AD_CONFIG__ = {
  enabled: true,
  url: 'https://example.com/',
  title: '案内タイトル',
  description: '短い案内文'
};
```

`url` は `http` または `https` のみです。広告主の秘密鍵や利用者情報はこの設定へ入れません。未設定・不正値・`enabled: false` の場合は広告枠を表示しません。
