# Business workspace API contract

CSV import does not create Auth accounts or send invitations. Employees sign in through the existing email verification flow; a first-time Auth account may be created by that flow. The business surface does not send LINE messages, store CSV source text, play participant names, answers, or recordings. Existing personal account APIs are unchanged.

All endpoints require a verified `Authorization: Bearer` session. The server resolves membership from the database; a client supplied organization header is not authorization.

- `POST /api/business/organizations` `{slug,name}` creates an organization. The verified caller becomes the owner. Owners may create at most three organizations.
- `GET /api/business/organizations` lists the caller's active memberships.
- `POST /api/business/organizations/:orgId/members/import` accepts `text/csv` with the exact header `email,display_name,department`, or JSON `{rows:[...]}`. The limit is 500 rows and 256 KiB. Duplicate rows fail; existing members are skipped. No Auth account is created.
- Membership access requires the current verified Auth email to continue matching `email_normalized`. If a user changes their Auth email, the old membership remains retained but inaccessible; an admin removes the old row and imports the new address.
- `PATCH /api/business/organizations/:orgId/members/:memberId` accepts `{status}` (`active`, `suspended`) or owner-only `{role}` (`admin`, `member`). Owners cannot be suspended/demoted. A suspended unclaimed row remains pending until a verified matching login claims it.
- `DELETE /api/business/organizations/:orgId/members/:memberId` removes only the organization membership; it never deletes the Auth account or personal data. Admins can remove members; owners can remove admins and members.
- `DELETE /api/business/organizations/:orgId` is owner-only and cascades the organization membership and policy rows. Deleting an Auth user cascades their organization membership; it does not recreate a pending member.
- `PUT /api/business/organizations/:orgId/policy` accepts `allowedThemeIds` and all five boolean `featureFlags`: `group_play`, `solo_play`, `theme_mix`, `audio`, `theme_tags`. The server rejects unknown flags and R18 themes. At least one of group/solo must remain enabled.
- `GET /api/business/organizations/:orgId/workspace` returns only policy-allowed static, non-R18 theme metadata and effective features.
- `POST /api/business/organizations/:orgId/sessions` accepts `{mode,themeIds,participantCount}`. Membership and policy are rechecked; mode, count, mix, and theme allowlist are enforced server-side. The response contains a non-R18 question snapshot and policy features. No participant names or answers are accepted.
- `GET /api/business/organizations/:orgId/activities` returns only the metadata (`id`, title, description, kind, participant bounds, and `cardCount`) for the eight server-owned activities. It requires an active member and `businessActivities` enabled; card text is returned only by the start endpoint.
- `POST /api/business/organizations/:orgId/activities/:activityId/sessions` accepts `{participantCount}` (the legacy body `activityId` is accepted only when it matches the path). It rechecks membership, `businessActivities`, `group_play`, the activity ID, and its min/max participant count, then returns the protected cards in an in-memory session snapshot. The default mode is `shared`; no answers are stored.
- `GET /api/business/organizations/:orgId/quizzes` returns published company quizzes to members. Owner/admin also receive drafts when `customQuiz` is enabled.
- `POST /api/business/organizations/:orgId/quizzes` and `PATCH /api/business/organizations/:orgId/quizzes/:quizId` are owner/admin-only company-content create/edit/publish/stop (draft) operations. There is no delete operation. Each quiz has 1–100 questions; each organization has at most 100 quizzes; title/description/question/answer/explanation limits are 120/500/1000/1000/2000 characters and the combined request payload is capped at 256 KiB. HTML is stored as text and must be escaped by clients when rendered.
- `POST /api/business/organizations/:orgId/quizzes/:quizId` starts a quiz only after rechecking membership, `customQuiz`, organization ownership of the quiz, and published status. A stopped/private quiz returns `QUIZ_NOT_FOUND` to members. The response mode is `shared`; employee answers are not persisted.
- `GET /api/business/organizations/:orgId/card-market` returns the seven official conversation catalog IDs plus published organization-owned sets visible to the active member's department (or `all`). The official catalog remains available through the existing activity API and is not part of the paid entitlement.
- `GET /api/business/organizations/:orgId/card-market/owner` returns owner/admin management metadata, including role, entitlement, departments, drafts and stopped sets. `GET .../card-market/sets/:setId` returns the latest cards to owner/admin only, including drafts/stopped sets; members must use play. `POST /.../card-market/sets` creates a draft or published organization set; `PATCH /.../card-market/sets/:setId` edits it; `POST /.../sets/:setId` explicitly duplicates it for a department variant; `POST /.../sets/:setId/stop` stops publication; and `POST /.../sets/:setId/play` starts a set after rechecking entitlement, membership, visibility, audience, min/max participant count, and `group_play`/`solo_play`.
- Card-market create/edit/publish/duplicate/play require a service-managed active organization entitlement. Missing, expired, or unavailable entitlement fails closed; stop and owner/admin viewing remain available so data can be retained. Entitlement grant has no public HTTP endpoint and is service-role/SQL managed.
- Card-market limits are technical limits: 1–100 cards per set, 100 sets per organization, explicit min/max participants within 1–8 (solo is 1/1, group is at least 2), title 120 characters, description 500, card text 1000, and combined request payload 256 KiB. These are not pricing quotas. Department visibility accepts only active departments already present in `organization_members`; member answers are never stored.

The five feature flags are `group_play` (2–8 participants), `solo_play` (one participant), `theme_mix` (up to three allowed themes), `audio`, and `theme_tags`. The three content flags are `businessActivities`, `customQuiz`, and `generalQuiz`; disabling a flag denies its corresponding API, including direct service RPCs. The defaults are all content flags and group/solo/audio/tags enabled, with theme mix disabled. Roles are owner, admin, and member: owners can manage admins and members and delete the organization, admins can manage members and policy but cannot change admins, and members can only start an allowed session.

Business API reads are limited to 3,000 requests/minute per client IP and 120/minute per verified user. Mutations are limited to 120/minute per client IP and 60/minute per verified user. User keys are derived only after Supabase verifies the bearer token.

Workspace metadata returns allowed themes for every member. It returns the full non-R18 catalog and member-management rows only to owners/admins; employee responses do not contain other members' email addresses.
Theme metadata includes `participantRule` (`solo`, `pair`, or `group`) and each session theme includes the same rule; clients must use the server response rather than importing the full catalog.

The shared CSV parser is exported from `dist/business-csv.js`: it requires UTF-8 (BOM accepted), the exact three-column header, strict quote rules, non-empty data, and rejects malformed or oversized input before member import.

The SQL migration makes direct table access unavailable to anon/authenticated roles and exposes only service-role RPCs. RPCs recheck actor membership and role internally. If the migration or service key is unavailable, business endpoints return `503 BUSINESS_MIGRATION_UNAVAILABLE`; personal endpoints remain unaffected.

Quiz creator/updater audit columns use `ON DELETE SET NULL`, so removing an admin Auth account does not prevent the organization-owned quiz from being retained. Employee answers are never written to the quiz tables.
